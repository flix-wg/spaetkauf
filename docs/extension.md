# Kurt for bahn.de

Shows historical late-arrival odds beside long-distance connections and marks Kurt’s pick: the highest chance of at least 30 % with another connection on the page that leaves within 2 hours and arrives at most 20 minutes later, the same rule as the app. It reads results already loaded by the traveller; it does not book or navigate. When a card already shows a delay or cancellation, its badge starts with "Delay already posted: won’t count", keeps its odds and loses Kurt’s mark; no other card gets it. Seat and occupancy notices are ignored.

Install: run `npm ci && npm run build` in `extension/` (it bundles the app's odds code from `frontend/src/core/` into `extension/dist/odds.js`), then open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select `extension/`. In the extension’s settings, set the Kurt server URL: the site that serves `/data/odds/` (HTTPS, or HTTP on localhost). Custom HTTPS servers ask for access on save. The popup toggles overlays and shows whether the site’s odds index loads, the last day of history, parser path, counts, last check and three parsed connections.

How it works: the service worker computes the odds itself, with the same code as the app. It fetches `/data/odds/index.json` and one file per train from the configured site and looks the route up on Transitous (`api.transitous.org`) to count a change. A session `declarativeNetRequest` rule sets `User-Agent: kurt-extension/<version> (+https://github.com/flix-wg/spaetkauf)` on the extension’s own Transitous requests, as Transitous asks of clients without a Referer. Like the app, it makes at most 60 `/plan` calls a day (kept in extension storage). If a train file is missing that card shows no odds; if the site is unreachable the page shows an error and retries. bahn.de layouts are read only by the built-in selectors.

Privacy: the Kurt site sees which train files are requested. Transitous gets the start and destination names and the departure time. Nothing is sent to bahn.de beyond the page the user loads. No tracking. Odds are cached for ten minutes in the service worker.

Tests from `extension/`: `npm test` (builds the bundle first; the golden cases in `test/golden.json` come from `scripts/export_golden.py` and the static odds in `frontend/public/data/odds/`); for the local browser integration run `npm run e2e`. Playwright and its Chromium channel must already be installed. Optional `SPK_SHOTS` sets the screenshot directory (default `~/tmp/spk-shots-real`). The integration test serves the fixtures and the static odds from one local server, checks the User-Agent rule, and blocks bahn.de and Transitous network access.

Limits: checked by hand on live bahn.de on 2026-11-14 (badges, Kurt’s pick, the explainer and Open in Kurt); the retry after a failed odds request and the popup were not tried live. The static version, which computes odds in the extension, has not been tried on live bahn.de yet. The pick only sees backups shown on the page, so it can miss one the app finds. Layout changes can defeat the built-in selectors. Odds describe past runs, not a prediction; with a change, the extension looks the route up on Transitous and counts a missed change like the app; when that fails, takes over 4 seconds, or the start station is unknown, only the last train’s history counts.
